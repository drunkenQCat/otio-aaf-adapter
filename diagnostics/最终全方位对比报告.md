## 一、关键差异 (CRITICAL) — 可能导致 Pro Tools 导入失败

### 1.1 OperationDef UUID ❌

| 项目 | DaVinci | OTIO |
|------|---------|------|
| OperationDef UUID | `9d2ea894-0968-11d3-8a38-0050040ef7d2` | `e4962321-2267-11d3-8a4c-0050040ef7d2` |
| ParameterDef name | `Amplitude` | `ParameterDef_Level` |
| ParameterDef UUID | `e4962321-2267-11d3-8a4c-0050040ef7d2` | `e4962320-2267-11d3-8a4c-0050040ef7d2` |

**影响**: Pro Tools 可能无法识别 Audio Gain 效果
**修复位置**: `aaf_writer.py` L29, L33, L1189, L1196, L1232, L1236

### 1.2 🔴 SourceClip StartTime 负值 (新发现!) ❌

OperationGroup 内部的 SourceClip → MasterMob 引用中：

| 项目 | DaVinci | OTIO |
|------|---------|------|
| StartTime | **始终为 0** | **大负数** (-28524000 ~ -33544000) |

**示例** (Slot 3, 叶经理_1):

| Clip | DaVinci start | OTIO start | OTIO start 绝对值 = ? |
|------|---------------|------------|----------------------|
| OG[1] (len=476000) | 0 | -28524000 | = Filler[0] length! |
| OG[3] (len=352000) | 0 | -30024000 | = Filler[0] + OG[1] + Filler[2] |
| OG[5] (len=384000) | 0 | -30672000 | 累加偏移 |
| OG[7] (len=294000) | 0 | -31076000 | 累加偏移 |
| ... | 0 | 持续递减 | |

**根因分析**: OTIO 导出时，OperationGroup 内部 SourceClip 的 StartTime 被设置为**相对于时间线起始位置的偏移量（负值）**，而 DaVinci 始终设为 **0**（因为 SourceClip 引用 MasterMob 从头开始播放）。

**影响**: 这是 **非常严重的结构错误**。负 StartTime 告诉 Pro Tools "从源素材开始之前 N 个采样点开始播放"，这会导致：
- Pro Tools 无法定位源数据
- 音频片段可能完全无声或被跳过
- 时间线偏移混乱

**修复**: OperationGroup 内部 SourceClip 的 StartTime 应始终设为 0（或等效的不设置该属性）

### 1.3 🔴 所有 SourceMob/MasterMob 长度不一致 ❌

92 个长度值全部不同，无一匹配：

| Mob | DaVinci Length | OTIO Length | 差值 |
|-----|---------------|-------------|------|
| A1-0001 | 476000 | 477023 | +1023 |
| A1-0002 | 352000 | 352175 | +175 |
| A2-0001 | 176000 | 384480 | **+208480** (完全不同的素材!) |
| A3-0001 | 398000 | 295727 | **-102273** (完全不同的素材!) |
| A2-0002 | 176000 | 513743 | **+337743** (完全不同的素材!) |

**注意**: 部分差异极小（<0.5%），可能是帧率转换精度问题；但部分差异巨大（>100%），说明 **OTIO 和 DaVinci 的素材到 Mob 的映射关系完全不同**。

**根因**: Mob 排序不同（见 1.4），同一个 mob index 对应的是不同的音频素材。

### 1.4 🔴 MasterMob 排序不一致 ❌

| Index | DaVinci (按轨道交叉) | OTIO (按素材分组) |
|-------|---------------------|-------------------|
| 1 | A1-0001_01_叶经理 | A1-0001_01_叶经理 |
| 4 | A1-0002_05_叶经理 | A1-0002_05_叶经理 |
| 7 | **A2**-0001_06_叶经理 | **A1**-0003_11_叶经理 |
| 10 | **A3**-0001_07_叶经理 | **A1**-0004_15_叶经理 |
| 13 | **A2**-0002_08_叶经理 | **A1**-0005_19_叶经理 |

- DaVinci 按**时间线中出现的轨道交叉排序**: A1, A1, A2, A3, A2, A1, A2, A2, A3...

**影响**: Pro Tools 可能依赖 Mob 排序来推断轨道分配。错误的排序会导致素材与轨道的对应关系混乱。

## 六、SourceClip StartTime 负值详细分析

这是本次分析发现的**最关键新问题**。

### 数据结构

```
CompositionMob
  └─ Slot 3 (audio, rate=48000)
       └─ Sequence
            ├─ [0] Filler (length=28524000)
            ├─ [1] OperationGroup (length=476000)
            │     ├─ Operation: Audio Gain
            │     ├─ Parameter: ConstantValue (1.0)
            │     └─ Input[0]: SourceClip
            │           ├─ length = 476000
            │           ├─ StartTime = 0 (DaVinci) / -28524000 (OTIO)  ← 差异!
            │           └─ SourceID → MasterMob
            ├─ [2] Filler (length=1026000)
            ├─ [3] OperationGroup (length=352000)
            │     └─ Input[0]: SourceClip
            │           ├─ length = 352000
            │           ├─ StartTime = 0 (DaVinci) / -30024000 (OTIO)  ← 差异!
            │           └─ SourceID → MasterMob
            ...
```

### StartTime 含义

- **DaVinci (StartTime=0)**: "从 MasterMob 的开头开始播放，播放 length 个采样"
- **OTIO (StartTime=-28524000)**: "从 MasterMob 开始之前 28524000 个采样处开始播放" — 这是无意义的，因为源数据不存在于负偏移位置

### 为什么 OTIO 产生负值

推测 `_create_audio_gain_opgroup()` 中的 SourceClip 创建逻辑可能错误地将**时间线上的累积偏移**写入了 SourceClip 的 StartTime，而不是简单地设置为 0。
